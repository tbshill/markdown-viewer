# Markdown Viewer

A read-only, very fast native macOS markdown viewer, plus a Quick Look extension so pressing the spacebar on a `.md` file in Finder shows a rendered preview.

## Features

- GitHub Flavored Markdown via [cmark-gfm](https://github.com/swiftlang/swift-cmark): tables, task lists, strikethrough, autolinks, footnotes, `tagfilter`, raw HTML (`<details>`, `<img>`, `<br>`).
- Code syntax highlighting (highlight.js, common languages), applied lazily as blocks scroll into view.
- Mermaid diagrams, rendered lazily and only loaded when a document contains a `mermaid` fence.
- Light and dark mode, GitHub-style typography.
- Handles multi-megabyte documents: parsing and templating run off the main thread.
- Live reload when the file changes on disk (survives editors' atomic saves), preserving scroll position.
- Zoom (Cmd +, Cmd -, Cmd 0) and Reload (Cmd R).
- External links open in your browser; relative links to other `.md` files open in the app.

## Requirements

- macOS 13 or later
- Xcode 15 or later (Swift 5.9)
- [XcodeGen](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen`

## Build

```sh
brew install xcodegen
xcodegen generate && open MarkdownViewer.xcodeproj
```

Select the `MarkdownViewer` scheme, choose your signing team under Signing & Capabilities (for both the app and the `MarkdownQuickLook` target; `DEVELOPMENT_TEAM` is blank in `project.yml`), and Run.

`project.yml` is the source of truth: the `.xcodeproj`, both `Info.plist` files and both `.entitlements` files are generated by XcodeGen.

## Enable Quick Look

1. Run the app once (this registers the embedded extension).
2. Move `MarkdownViewer.app` to `/Applications`.
3. Reset Quick Look: `qlmanage -r && qlmanage -r cache`
4. Check System Settings > General > Login Items & Extensions > Quick Look (older macOS: Extensions) and make sure *Markdown Quick Look* is enabled.
5. Test: `qlmanage -p Samples/showcase.md`, or select a `.md` file in Finder and press space.

If another app also claims markdown previews, the order can be changed in the same settings pane.

## Architecture

```
MarkdownViewer/            SwiftUI app (DocumentGroup(viewing:)), WKWebView host, file watcher
MarkdownQuickLook/         QLPreviewingController extension hosting a WKWebView
Packages/MarkdownCore/     Shared library
  MarkdownRenderer         cmark-gfm C API wrapper: markdown -> HTML fragment
  HTMLTemplate             wraps the fragment in a page, inlines CSS/JS from bundled resources
  Resources/               markdown.css, viewer.js, highlight.min.js, mermaid.min.js (see VENDOR.md)
```

- Both the app and the extension call `HTMLTemplate.render(markdown:title:baseURL:)` and `loadHTMLString`.
- Security: raw HTML is enabled (`CMARK_OPT_UNSAFE`) so common GitHub-style markup works, but `tagfilter` neutralises `<script>`, `<iframe>`, `<style>` and friends, and every page carries a strict Content-Security-Policy: scripts only run with a per-page nonce (only our bundled scripts have it), no connections, no frames, no forms.
- Sandbox: both targets are sandboxed with read-only access to the user-selected file. `network.client` is required for the WKWebView WebContent process under the sandbox. Because the sandbox grants only the selected file, images referenced relatively next to the document may not load (see Known limitations).

## Performance notes

- cmark-gfm is a fast C parser; the Swift side feeds it the raw UTF-8 buffer in a single call and frees everything deterministically.
- Rendering never happens on the main thread.
- CSS and JS are read from the bundle once (static lets). The 2.5 MB Mermaid bundle and the highlighter are only inlined when the document uses them, determined with a byte-level search.
- In the page, Mermaid diagrams (800 px margin) and code blocks (1000 px margin) are processed via `IntersectionObserver` as they approach the viewport; highlighting is time-sliced per frame, skips blocks over 200 KB, and never auto-detects languages.
- Live reload keeps the scroll position by reading `window.scrollY` before reload and restoring it after `didFinish`.

## Known limitations

- Relative images/links: `loadHTMLString` with a `file:` base URL and the App Sandbox may block local image loading. If that matters, options are a custom `WKURLSchemeHandler`, or writing the HTML next to the document and using `loadFileURL(_:allowingReadAccessTo:)` (needs a non-sandboxed build or a user-granted folder).
- Mermaid theme is chosen at load time and does not follow later appearance changes.
- Cmd + is bound as `+` (Cmd-Shift-=).
